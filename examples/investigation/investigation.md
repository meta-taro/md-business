# 返却の記録が二重に入る件の調査

## 経緯

総務から「返却の画面でエラーが出る」と連絡があった。返却は済んでいるのに
赤い表示が出る、という内容だったため、記録が二重に入っているかを確かめた。

## 調べ方

1. `search_lines` で `POST /loans/*/return` の行を抜き出した
2. 貸出 ID ごとに件数を数え、2 件以上あるものを拾った
3. 該当した前後の行を `read_lines` で読み、`save_evidence` で残した

## 所見

### F-01 同じ貸出 ID への返却要求が 1 秒以内に 2 件届いている

`loan-2871` に対する `POST /loans/2871/return` が `11:04:07.312` と `11:04:07.884` の
2 回記録されている。送信元は同じ端末で、間は 0.57 秒。根拠は `evidence/EV-001.md`。

利用者に確認したところ、押しても画面がすぐ変わらないのでもう一度押した、とのことだった。

### F-02 2 件目は 409 で弾かれており、記録は二重になっていない

1 件目は `200`、2 件目は `409 ALREADY_RETURNED` を返している。根拠は `evidence/EV-002.md`。
データベース側の `loans.returned_at` も 1 件だけ入っており、記録は壊れていない。

## 結論

記録は二重になっていない。総務が見た赤い表示は、2 回目の押下に対する
`409 ALREADY_RETURNED` がそのまま出たもの。**データの問題ではなく画面の問題**。

## 次にやること

| 項目 | 誰が |
|---|---|
| 押した直後にボタンを効かなくする | 画面担当 |
| 返却済みの貸出への返却は、赤ではなく「もう返却済みです」と出す | 画面担当 |
| 記録の重複が無いことを総務へ伝える | 調査担当（連絡済み） |

返す側の API は変えない。二重の要求を弾いているのは仕様どおりの動きで、
ここを緩めると本当に二重に記録される道ができる。
