# 実例

[`templates/`](../templates/) が「白紙の型」なのに対して、ここは**中身の入った実物**です。型だけ見ても、実際に書くとどうなるかは分かりません。

置いてあるのは、架空の会社の**社内備品の貸し出し管理**という 1 つの案件です。文書どうしが互いを参照しているので、設計から検証シート、備品を買った請求書まで、1 本の流れとして読めます。

| ファイル | スキーマ | 中身 |
| --- | --- | --- |
| [`project-docs/spec.md`](./project-docs/spec.md) | `spec/v1` | 基本設計書。範囲・機能・画面・決めたこと |
| [`project-docs/api-spec.md`](./project-docs/api-spec.md) | `api-spec/v1` | API 詳細設計書。エンドポイントとエラー |
| [`project-docs/db-spec.md`](./project-docs/db-spec.md) | `db-spec/v1` | DB 設計書。テーブル・列・インデックス |
| [`project-docs/test-spec.tsv`](./project-docs/test-spec.tsv) | `test-spec-tsv/v1` | 検証シート。デスクトップアプリでは表として開く |
| [`invoice/invoice.md`](./invoice/invoice.md) | `invoice/v1` | 適格請求書。貸出用のタブレットの代金 |
| [`investigation/`](./investigation/) | `investigation/v1` | 調査報告書と、その根拠として残した控え |

## アプリの側を確かめたいときは

[`try-it/`](./try-it/) に、**ひととおり開いて押して転がすための一式**を別に置いています。
6 種類のスキーマ・素の Markdown・大小の表・外から届いた JSON / XML・HTML・画像・
4,200 行のログまでを、別の架空案件（会議室の予約）で一式そろえたものです。
読み物としてではなく、見え方と動きを見るために使ってください。

## 中身は全部つくりものです

会社名・登録番号・口座・住所・社員コードは実在しません。`T1234567890123` は登録番号として通らない番号で、`example.com` は文書用に予約されたドメインです。**形を写して、値は写さないでください。**

## `結果` 列をわざと空けています

検証シートの `結果` はすべて `未実施` のままです。行を起こすのは書く人（AI のこともあります）で、
**OK / NG を付けるのは、実物を動かして目で見た人**です。この 2 つを分けておくことがシートの目的で、
書いた本人が自分で丸を付けたシートは、何も記録していないのと同じになります。

## 開き方

- **デスクトップアプリ** — このフォルダを開きます。Markdown はプレビュー付きで、`test-spec.tsv` は編集できる表になります。
- **Chrome 拡張** — `.md` を開くとプレビューと A4 PDF 出力ができます。
- **MCP サーバー** — AI エージェントにこのフォルダを渡すと、同じスキーマで読み・検証・更新ができます。

ここの Markdown は、テンプレートと同じように CI で JSON Schema にかけています。壊れた例を配ると、読んだ人が壊れた形を真似るためです。
