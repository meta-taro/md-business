# 1. 概要

## 1.1 背景

社内の貸出備品（ノート PC・タブレット・プロジェクタなど）は、総務部門が紙の台帳で管理している。
台帳が総務の席にしか無いため、借りる側は席まで行かないと空きが分からず、
返却の記入漏れがあると次に借りる人が見つけられないまま探し回ることになる。

## 1.2 目的

- 誰が何をいつまで借りているかを、席を離れずに確認できるようにする
- 返却の記入漏れを、期限を過ぎた貸出の一覧として総務が拾えるようにする
- 台帳を Markdown と TSV で持ち、表計算や PDF へ出せる形のまま残す

## 1.3 スコープ

| スコープ | 含む / 含まない |
|---|---|
| 備品の登録・更新 | 含む |
| 貸出・返却の記録 | 含む |
| 期限超過の一覧 | 含む |
| 備品の購入・廃棄の稟議 | 含まない（既存の稟議手続きを使う） |
| 社員名簿の管理 | 含まない（人事システムを参照する） |

## 1.4 用語

| 用語 | 定義 |
|---|---|
| 備品（Asset） | 貸し出しの単位。管理番号を 1 つ持つ |
| 貸出（Loan） | ある備品をある社員が借りている期間 |
| 返却期限（Due） | 貸出時に決める、返してもらう日 |
| 期限超過（Overdue） | 返却期限を過ぎて返却の記録が無い貸出 |

# 2. システム構成

## 2.1 全体像

社内ネットワークに置いた 1 台のサーバーで完結する。外部サービスへは接続しない。

| 層 | 使うもの | 役割 |
|---|---|---|
| 画面 | 社内 Web | 備品一覧・貸出・返却の操作 |
| API | REST | 画面と同じ操作を機械からも行えるようにする |
| 保管 | PostgreSQL | 備品と貸出の記録 |

## 2.2 外部との接点

社員の氏名と所属は人事システムの読み取り専用ビューを参照する。本システムでは持たない。

# 3. 機能

## 3.1 備品を登録する

管理番号・品名・区分を入れて登録する。管理番号は重複を許さない。

## 3.2 借りる

空いている備品を選び、返却期限を入れて貸し出す。既に貸出中の備品は選べない。
返却期限の既定は貸出日の 14 日後で、延ばす場合は総務の承認を要る扱いにする。

## 3.3 返す

貸出中の備品に返却の記録を付ける。返却済みの貸出へ重ねて記録することはできない。

## 3.4 期限を過ぎたものを見る

返却期限を過ぎて返却の記録が無い貸出を、超過日数の多い順に並べて出す。

# 4. 画面

| 画面 | 内容 |
|---|---|
| 備品一覧 | 区分での絞り込み。貸出中は借りている人と期限を出す |
| 貸出 | 備品を選び、借りる人と返却期限を入れる |
| 返却 | 管理番号を入れて返す |
| 期限超過 | 超過日数の多い順の一覧。総務が見る |

# 5. 決めたこと

## 5.1 予約は作らない

「先に押さえておきたい」という要望はあったが、台帳の置き換えを先に済ませる。
予約を入れると、押さえたまま借りに来ない分を誰が解放するかを決める必要があり、
それは紙の台帳でも解けていない。運用が乗ってから改めて考える。

## 5.2 削除はしない

備品も貸出も、記録を消さずに状態で表す。台帳では消しゴムで消された行が残らず、
「あったはずのものが無い」の追跡ができなかった。

# 6. 積み残し

| 項目 | 扱い |
|---|---|
| 予約 | 運用が乗ってから改めて判断する（5.1） |
| バーコード読み取り | 管理番号の手入力が負担になれば検討する |
| 通知 | 期限前の連絡は当面メールを手で送る |
