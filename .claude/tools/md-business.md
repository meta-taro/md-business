# md-business — 道具カード（正本）

> **これは司令塔が持つ正本です。**配布リポの `.claude/tools/md-business.md` は、このファイルのコピー。
> 内容を変えるときはここを直してから配る。Issue 本文へ書き写して配らない
> （Issue へ書くと更新経路が無くなり、古い前提がそのまま残る）。

Markdown を正本にした業務文書（請求書・検証シート・設計書）のビューワー兼編集環境。
**AI エージェントからは MCP サーバー経由で読み書きする。**
横断ノウハウ側の参照元: `.claude/browser-verification.md` §0（§22 検証シート・§36 改善要望シート）。

- リポジトリ: <https://github.com/meta-taro/md-business>（MIT）
- ダウンロード: <https://meta-taro.github.io/md-business/download/>
- マニュアル: <https://meta-taro.github.io/md-business/manual/>（日本語: `/manual/ja/`）
- リリース: <https://github.com/meta-taro/md-business/releases/latest>

## 版数はこのカードに書かない

**開発が速く、版数を書いた翌日には嘘になる**（実測 2026-08-20〜21 の 24 時間で v0.14 → v0.21 の 8 リリース）。
入手は必ず上のダウンロードページを開いて、そこに出ている最新を取る。

## 1. デスクトップアプリ

**入手はダウンロードページから。** <https://meta-taro.github.io/md-business/download/>

Windows は `.msi`（推奨）または `.exe`、macOS は `.dmg`（Intel / Apple Silicon 共通）。

### 初回起動時に警告が出ます（異常ではありません）

**コード署名・公証を行っていないため、OS が「発行元不明」として止めます。**

- **Windows**: SmartScreen が出る場合がある
- **macOS**: 未公証のため、**初回のみ Finder で右クリック →「開く」**（ダブルクリックでは Gatekeeper に弾かれる）

**警告が出たこと自体は不具合ではないので、Issue に起こさなくて構いません。**
逆に**警告が出ずに入った場合は、別の何かが起きている**ので報告してください。

### 更新は自動

リリースに `latest.json` と `.sig` が同梱されており、**アプリが自分で更新を取りに行きます**。
手で入れ直す必要はありません。**だから「古い版が入ったまま」は起きません。**

### 既定のインストール先（Windows）

```
%LOCALAPPDATA%\md-business\md-business-desktop.exe
```

`Program Files` ではなくユーザー配下に入る。管理者権限なしで入るぶん、
「入れたのに `Program Files` に無い」で見失いやすい。

## 2. MCP サーバー

**2 通りあります。どちらを使っているかを取り違えると版ずれで詰まります。**

| | 入手 | 版 |
|---|---|---|
| **A. アプリ内蔵**（推奨） | デスクトップアプリを起動すると自動でローカル MCP サーバーが立つ | **アプリの版に追従する** |
| **B. ソースビルド** | リポジトリを clone してビルド | **リポジトリの版**。npm 未公開 |

### A. アプリ内蔵（推奨）

アプリが `mcpServers` の JSON をクリップボードにコピーするので、それを貼るだけ。
接続情報は再起動をまたいで保持される。

> **注意**: この経路は**アプリを入れてからでないと JSON を見られません。**
> 入れる前の AI エージェントは形が分からないので、初回は人間が 1 度貼る必要があります。

### B. ソースビルド

```sh
git clone https://github.com/meta-taro/md-business
cd md-business
corepack enable
pnpm install
pnpm -r build
```

登録（コピペ 1 行）:

```sh
claude mcp add md-business -- node <clone 先>/packages/mcp-server/dist/bin.js <対象フォルダの絶対パス>
```

> **npm には公開されていません**（2026-08-15 実測: レジストリが 404）。
> `npx -y @md-business/mcp-server` は使えません。**解消されたらこのカードを更新すること。**

### 版ずれに注意（実際に起きた事故）

**アプリ側とソース側で版が割れ、アプリで使える新機能が MCP 側に無い、という詰まり方をしました。**
B（ソースビルド）を使っているなら、アプリを更新したときに**必ず `git pull` + 再ビルドまでやる。**

**A（アプリ内蔵）を使っているなら、この事故は起きません。**アプリが自動更新され、
内蔵 MCP はアプリの版に追従するため。**版ずれが構造的に起きるのは B だけ。**

確認コマンド:

```sh
claude mcp list                                   # どのパスの MCP を掴んでいるか
node <clone 先>/packages/mcp-server/dist/bin.js --version 2>&1 | head -1
```

## 3. 使えるツール（28 個・2026-08-21 実測）

**以前 Issue で配ったカードには 14 個しか載っていませんでした。**とくに**調査系（ログ・HAR・外部データ）が
丸ごと抜けており**、使えるのに使われていない状態でした。以下が実登録の全部です
（出典: `packages/mcp-server/src/server.ts` の `registerTool` 呼び出し）。

### 業務文書（Markdown）

| ツール | 何をする |
|---|---|
| `list_schemas` | 扱える業務文書スキーマの一覧（id + 日本語ラベル） |
| `get_schema` | スキーマ id を指定して JSON Schema 本体（必須項目・型・選択肢）を返す |
| `read_document` | 文書を読み、frontmatter / body / 検出スキーマを返す |
| `validate_document` | 既存文書を宣言スキーマで検証（schema 未宣言は invalid 扱い） |
| `create_document` | 新規作成。schema 宣言キーを種別ごとに自動注入。既存パスは上書きしない |
| `update_document` | frontmatter（浅くマージ）／本文を更新。更新後に再検証し、前後の行 diff を返す |
| `search_documents` | 全文・スキーマ・日付範囲で検索。文書と検証シートの両方を一覧できる |

### 検証シート（TSV・§22）

| ツール | 何をする |
|---|---|
| `read_tsv` | メタ情報・列定義（型 / 必須 / 選択肢）・データ行・列型の検証結果を返す |
| `append_tsv_row` | 末尾に 1 行追加。値は列名キーで指定し、未指定の列は空セルのまま |
| `update_tsv_row` | 既存 1 行のうち、指定した列だけを差し替える |
| `check_tsv` | シートの形（列型・必須・マジック行）を検証する |

**全文を書き直さない。**「1 レコード = 1 物理行」が崩れると差分が読めなくなる。
`rowIds` が空でなければ**行 ID で指す**（行 index は 1 行挿すだけでずれる）。

### 調査（ログ・通信・外部データ）— **配ったカードに一切載っていなかった部分**

| ツール | 何をする |
|---|---|
| `search_lines` | ログを正規表現で行検索し、一致行を行番号つきで返す（前後の行も取れる） |
| `read_lines` | 行範囲を行番号つきで返す。`search_lines` で見つけた箇所の周辺を読む |
| `filter_records` | 1 行 1 レコードのログ（JSONL / TSV）を条件で絞る。式は受け付けず演算子の組み合わせ |
| `aggregate` | 絞ったレコードを時間帯別・キー別に数える。「いつ・何が・何件」を先に掴む |
| `build_timeline` | 別々のログの行を時刻順に 1 本へ混ぜる。出どころと行番号を保ったまま並ぶ |
| `read_har` | 通信の記録（`.har`）を読む。index を省けば概況、指せばその 1 件 |
| `read_data` | 外部から届いた JSON / XML を木構造として読む（読むだけ・書き戻す口は無い） |
| `data_to_table` | JSON / XML の繰り返しを Markdown の表に写す。出典行つき。ファイルには書かない |
| `save_evidence` | 取り出した中身を Evidence として 1 件 1 ファイルに残す。既存は上書きしない |

**使いどころ**:

- **「繋ぐと失敗する」の調べ物は、コードを読む前に `read_har` で失敗した往復を特定する。**
- **ログの全文を開かない。**文脈が埋まるうえ、`Authorization` / `Cookie` / `token` /
  メールアドレスが伏せ字を通らずに入る。上のツールの戻り値は**必ず伏せ字がかかり**、
  上限で切ったときは切ったと返る。
- 木から自前で表を組むと列の抜けや `|` による桁ずれが起きるが、**壊れた表は読める形をしているので気づけない。**
  だから `data_to_table` を使う。

### git

| ツール | 何をする |
|---|---|
| `git_status` | ブランチ・upstream との差・変更ファイル一覧 |
| `git_diff` | HEAD と作業ツリーの差分を unified diff で。パス指定で 1 ファイルに絞れる |
| `git_commit` | ステージしてコミット（**push はしない**）。ハッシュと最新の変更状況を返す |

### デスクトップアプリの操作・出力

| ツール | 何をする |
|---|---|
| `open_document` | アプリの表示を対象文書に切り替える。印刷は伴わない |
| `list_open_documents` | 今開いている文書の一覧。どれが手前か、未保存の編集が残っているかも分かる |
| `close_document` | 開いている文書を閉じる。未保存の編集は先に保存してから |
| `open_in_app` | 対象をアプリで開く |
| `export_pdf` | 対象文書を開き、PDF 出力（印刷）ダイアログを表示する（**保存先は人間が決める**） |

### 全体の約束

- **すべての呼び出しが宣言されたスキーマで検証される**
- **`git push` は意図的に提供されていない。**秘匿情報も MCP を通らない
- 到達範囲は**アプリで開いているフォルダ内のみ**。loopback バインドで、
  トークンが一致しないリクエストは拒否される
- **このサーバー自身の作業ログ**は `.md-business/logs/<YYYY-MM-DD>.jsonl` に 1 日 1 本。
  上の調査系ツールがそのまま使える

## 4. ワークスペースの `.md` / `.tsv` を直接編集しない

汎用のファイル読み書きでも書き換えられるが、そうすると 3 つ失われる。

- **スキーマ検証**: 素の編集では壊れたまま気づけない
- **画面反映**: 利用者は同じファイルをアプリで開いている。ツール経由の書き込みだけが即座に画面へ出る
- **操作ログ**: AI が何を触ったかは MCP タブに残る。素の編集は記録されず、利用者から追えない

### 触ってはいけない宣言

- `directives` の `hidden` — 利用者が表から外して控えにした行。`read_tsv` にも出ず書き換えもできない。
  **アプリ側の操作なので、宣言を書き換えて戻そうとしない**
- `directives` の `computed` — 値がほかから決まる列（例 `computed No. = rowNumber()`）。
  指定すると書き込みは失敗する。「実数で埋めて」と言われても**それは宣言を直す話であって
  セルを打つ話ではない**。打てば集計が消えたまま提出物として出る

## 5. 既知エラー（文言そのまま）

### グリッドで開かない / 表にならない

1 行目のマジック行 `#! md-business:test-spec-tsv/v1` が**行頭 0 桁**にあるか確認する。
判定は**内容ベースで、拡張子は見ていない**。

### 値が左隣の列に入っている

**区切りタブが 1 個足りない。**短い行（末尾の空セル省略）は仕様上許容されるため、
ずれ先が text 列だと `validateTsv` が issues 0 で素通りする。
**テキストエディタで手打ちしない**（グリッド編集か `update_tsv_row` を使う）。

### 行がずれる

セル内改行を実改行で入れている。`
`（バックスラッシュ + n）で書く。
