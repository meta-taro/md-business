# Changelog — @md-business/desktop

このアプリの変更履歴。バージョンは [Semantic Versioning](https://semver.org/lang/ja/) に従う。

英語版は [CHANGELOG.en.md](./CHANGELOG.en.md)。版を足すときは両方に足す（片方だけだとテストで落ちる）。

## 0.13.0

### 追加

- **文書を複数開いて、タブで行き来できるようになった**。開けるのは 1 つだけだったので、設計書と検証シートを突き合わせる、請求書を並べて見る、といった読み方ができなかった。未保存のタブは閉じる前に保存する。別のタブを見ている間に手元の外でファイルが書き換わっても、戻ったときに印で分かる。検証シートは、どこを選んでいたか・どこまで送っていたかをタブごとに覚えている。
- **表の数値から図を描けるようになった**。本文に `chart` の囲みで「どの表の・どの列を・どう描くか」を書くと、折れ線 / 棒 / 円になる。数字は表のまま置いておけるので、表を直せば図もその場で変わる（図の中へ数字を書き写さない）。描けなかったときは、その理由と書いた指定がそのまま残る。

### 修正

- **画像として書き出したとき、本文に貼った画像が抜けていたのを直した**。撮影は別に立てた画面で行うため、そこに画像を運んでいなかった。プレビューでは見えているので、書き出したものを開くまで気づけない。
- **作図（Mermaid）が、HTML・画像・サイトの書き出しでは囲みのまま出ていたのを直した**。画面と PDF には出ていたぶん、書き出しでだけ図が文字列に戻る。

## 0.12.0

### 追加

- **画像をアプリの中で開いて見られるようになった**。これまでは一覧に出ないので、写真やスクリーンショットを確かめるだけでもアプリの外でフォルダを開くしかなかった。全体に合わせる / 原寸を切り替えられ、大きさとファイルの容量も分かる。
- **文書に貼った画像が、プレビューと書き出しに出るようになった**。`![](./図.png)` のように隣のファイルを指しても、これまでは何も出ないまま抜けていた。単一 HTML の書き出しには画像も一緒に入るので、送った先でも崩れない。フォルダをまとめて書き出す静的サイトでは、画像をファイルとして運ぶ（ページごとに埋め込まないので、同じ写真を何枚もの文書で使っても重くならない）。書き出す前のブラウザ表示でも同じものが見える。

### 変更

- **指し先の無い画像・フォルダの外を指す画像があっても、文書そのものは出るようにした**。出ないのはその 1 枚だけで、残りの本文と画像はこれまでどおり読める。

### 既知の制限

- `<img src="図.png">` のように HTML で直接書いた画像は出ない。本文を HTML にする段階で素の HTML を落としているため。`![](図.png)` の書き方であれば出る。

## 0.11.0

### 追加

- **コミットに含めるファイルを選べるようになった**。これまでは変更のあったものが一括で対象になっていたので、途中まで書いたファイルを抱えていると区切ることができず、まとめて 1 つのコミットにするか、アプリの外で `git` を叩くかしかなかった。
- **コミット履歴を変更管理の画面で見られるようになった**。今の変更しか見えないと、直前に何を入れたかを確かめるのにアプリの外へ出ることになる。
- **Git 管理下でないフォルダを、その場でリポジトリにできるようになった**。これまでは変更管理の機能が丸ごと使えず、先に別のツールで `git init` する必要があった。
- **共有リンクで、相手の手元に同じ文書を開けるようになった**。同じリポジトリで文書を共有していても、「どのファイルのことか」は口頭やチャットで伝えるしかなかった。リンクを渡せば、受け取った側は押すだけで同じ場所に着く。アプリが起動していなければ起動し、していれば前面に出る。
- **AI からも、開いてほしい文書を指定できるようになった**（内蔵の MCP サーバー）。フォルダがまだ開かれていなければ、そのフォルダを開いてから表示する。

### 変更

- **履歴の読み取りとリポジトリ作成の間、画面が固まらなくなった**。コミット数の多いリポジトリでは、読んでいる間ずっと操作を受け付けなかった。

### 修正

- **AI にファイルを指定してコミットを頼んだとき、別の変更が紛れ込まなくなった**。指定されたファイルを対象に加えるだけで、既に別に加えてあった変更をそのまま巻き込んでいた。紛れ込んだことは後から履歴を見るまで分からない。

## 0.10.1

### 修正

- **検証シートで文字を打つたびに待たされることがあったのを直した**。別のシートを指す列（リンク・件数の集計・選択肢を別シートから引く列）があると、1 文字打つごとに参照先のファイルを読み直していた。読む相手は表の見出しだけで決まっていて、打った内容とは関係がない。参照先が共有フォルダなど手元にない場所にあると、その読み取りがそのまま打鍵の待ち時間になっていた。
- **プレビューを一度開いたあとに検証シートを編集すると重くなるのを直した**。表を出している間も、誰も見ていないプレビューを 1 文字ごとに本文全体から組み直していた。

## 0.10.0

### 追加

- **調査した内容を、そのまま提出できる形で残せるようになった**。調査報告書を開くとプレビューに整形して出る。根拠の欄は文章を受け付けず、どのファイルの何行目かという参照だけを受ける。「そう見えた」で書かれた報告と、後から同じファイルだと確かめられない報告を作らせないため。
- **複数のログを、時刻の順に混ぜて並べられるようになった**（時系列）。どの行も、どのファイルの何行目から来たかを持ったまま並ぶ。調べるときに知りたいのは 1 本のログの中の順番ではなく、複数のログを跨いだ順番なので、これまでは人が手で突き合わせていた。
- **プレビューで見ているものと同じ HTML を、1 ファイルとして書き出せるようになった**。これまでの出力は PDF だけで、PDF は紙面の都合が強く、画面で見るのにも人に送るのにも向いていなかった。画像も体裁もその 1 ファイルに入るので、送った先で崩れない。
- **フォルダの文書をまとめて、静的なサイトとして書き出せるようになった**。文書が何枚もあるものを人に渡すには 1 ファイルの書き出しでは足りない。書き出し先はフォルダ直下の `dist/` で、文書どうしのリンクはそのまま辿れる。
- **書き出す前に、開いているフォルダをブラウザで見られるようになった**。この PC の中だけに届くアドレスに出すので、外からは見えない。`dist/` を作らずに下見できる。
- **開いている文書を PNG / JPEG として書き出せるようになった**（Windows）。資料に貼る・チャットに貼るときに、PDF を開いて撮り直す手間が要らない。アプリが既に持っている表示機構で撮るので、インストーラは重くならない。
- **プレビューを、スマートフォンの幅で見られるようになった**。狭い画面でどこで折り返るかは、幅を変えて組み直させないと分からない。縮小して見せるのでは字が小さくなるだけで、折り返しは PC のままになる。
- **AI から、画面に出す文書を切り替えられるようになった**（内蔵の MCP サーバー）。これまで表示を動かす口は PDF 出力しか無く、見せたいだけのときも印刷まで走っていた。開いているフォルダの外は開かない。

### 変更

- **起動がさらに軽くなった**。窓が出るまでに読む JS が 1,009KB から 298KB になった。まだ何も開いていない時点で、6 種類ぶんの検証器・PDF 描画一式・変更履歴の全文まで読み終えるのを待っていた。
- **文書を開くときに読むものを、その文書の書式ぶんだけにした**。請求書を 1 枚開くのに、API 仕様書や DB 設計書の検証器まで読み込んでいた。
- **文書のアクセント色（見出し・罫線・強調の色）の受け方を 1 か所にまとめた**。同じ処理が書式ごとに写してあったため、片方だけ扱いが違っても出来上がりを並べるまで気づけなかった。読めない色を指定したときは、黙って落とさずに知らせる。

### 修正

- **起動のたびに黒いウィンドウが開いて消えるのを止めた**。Windows で、操作できるようになるまでの間にコンソールウィンドウが 3 つ開いていた。窓は前面を奪うので、その間のクリックが入らなかった。
- **検証グリッドで、セルを選んだままスクロールすると表示が揺れるのを直した**。選んだ行へ引き戻されるため、行数の多いシートほど読めなくなっていた。
- **ネットワーク越し（共有フォルダ）のフォルダを開くと固まるのを直した**。一度踏むと、次に起動したときのフォルダ復元でも同じ状態になっていた。フォルダの走査がメインの処理を止めていたため。
- **入力したあと、続けて打つと固まるのを直した**。自動保存のあとに走る変更点の確認が、その間ずっと画面を止めていた。ファイルの読み書きと git の呼び出しを、画面を止めない場所へ移した。
- **検証グリッドの編集中に Ctrl+Z / Ctrl+Y が効かないのを直した**。編集中の取り消しだけがブラウザ任せになっており、そこでは何も起きない作りだったため、押しても無反応だった。取り消しの単位も 1 文字ずつではなく、そのセルに打った分をまとめて 1 回で戻すようにした。
- **検証グリッドで、長い文が入った行のあるシートをスクロールすると、表が揺れてがたつくのを直した**。折り返して高くなった行のぶんだけ、スクロールに合わせて表全体の高さが変わっていた。

## 0.9.0

### 追加

- **プレビューに図（Mermaid）が出るようになった**。設計書に書いた流れ図やシーケンス図が、コードのまま並ぶのではなく図として描かれる。図を書く場所と図が出る場所がこれまで食い違っていた。
  - 図が 1 つも入っていない文書では、図を描くための本体を読み込まない。図を使わない人の表示を重くしないため。
  - 描けなかった図は、元の文字のまま残す。書きかけの図で本文が消えないようにするため。
  - PDF にもそのまま載る。拡大しても粗くならない形で、図が紙の途中で割れないようにしている。
- **検証シートの列から、別のシートを指せるようになった**。ある列の値が別シートのどの列に載っているはずかをヘッダに 1 行宣言すると、突き合わせが自動で走る。表計算で関数を並べて手で保っていた対応表が要らなくなる。照合は両方向で、指した先に無い値と、どこからも指されていない行の両方が出る。
- **指されている件数を、列として数えられるようになった**。「この観点に紐づく試験が何件あるか」を、シートを開くたびに数え直さなくてよい。
- **選択肢を、別のシートの列から引けるようになった**。選択肢を列の宣言に並べると、増減のたびに使っている全シートのヘッダを直すことになる。一覧が既にシートとして存在するなら、そちらを正本にできる。
  - 参照先を開けないときは、その列を検査しない。選べる値は出ないが、書いてある値はそのまま残る。参照先を開いていないだけで既存の値が一斉に赤くなると、直しようのない赤に本物の違反が埋もれるため。
- **検証グリッドの行番号を右クリックして、行の操作を出せるようになった**（複製 / コピー / クリア / 控えに / 削除）。下の行操作バーはボタンが増え、窓を狭めると畳まれるので、よく使うものを行の上からも出せるようにした。効くのは右クリックした 1 行だけで、開くときに選択をその行へ寄せる。どの行に効くかが押す前に見える。
- **行を最後に変えたのが誰でいつかを、行の上で見られるようになった**（履歴）。検証シートは複数人が同じファイルの別々の行を触るので、NG が付いた行が今日の実施結果なのか半年前のまま残っているのかが表からは分からなかった。行番号に当てると「3 日前 · 誰 · 何をした変更か」が出る。変更履歴を毎回読みにいくので既定は切ってあり、行操作バーのボタンで入れる。履歴の無い行には何も出さない。
- **AI が、ログを全文読み込まずに調べられるようになった**（内蔵の MCP サーバー）。行の検索・行範囲の取り出し・1 行 1 件のログの絞り込み・時間帯別の集計・別々のログを時刻順に混ぜること・取り出した根拠の保存の 6 つ。ログを丸ごと渡すと、調べ始める前に読める量が尽きるうえ、認証情報やメールアドレスが伏せ字を通らずに混ざる。業務文書の読み書きとは別の口にしてある。
- **調査報告書の書式を足した**。ログ調査とネットワーク調査を 1 つの書式で扱う。根拠の欄には文章を書けず、構造化した参照だけを受け付ける。対象ファイルにはハッシュが要る。「そう見えた」が混ざった記録と、後から同じファイルだと確かめられない記録を作らせないため。今のところ AI 側（MCP）から作成・検証できる。

### 変更

- **起動が軽くなった**。窓が出るまでに読んでいた約 1,660KB のうち 6 割強はエディタ一式で、まだ何も開いていない段階では 1 バイトも要らないものだった。ファイルを開いたときに読むよう分けた。
- **セルの中の改行を、表計算ソフトと同じ操作に合わせた**。Alt + Enter / Ctrl + Enter / Shift + Enter のどれでも改行が入る。改行の合図はソフトによって分かれるので、覚え違いで確定してしまわないよう全部受けるようにした。修飾キーなしの Enter は、これまでどおり確定して下のセルへ。
- **改行を入れられる列が、見出しで分かるようになった**（列名のうしろの ↵）。どの列で効くかは打ってみるまで分からず、効かない列では確定して下の行へ落ちてしまうため。

### 修正

- **アプリの中のリンクを押しても何も起きなかったのを直した**。更新のお知らせの「もっと見る」、ヘルプの中の案内、プレビューや検証シートに書いた外部リンク、ファイルを右クリックしての「フォルダで表示」が、いずれも押しても無反応だった。ブラウザやエクスプローラーを開く権限に、開いてよい行き先の指定が抜けていたため、アプリの中で断られていた。断られたことを画面に出していなかったので、押した側からは壊れているのか自分の操作が悪いのか分からない状態だった。
  - 同じ抜けが起きたらテストで落ちるようにした。この種の抜けはビルドも型検査も通ってしまい、人が押してみるまで気づけないため。
- **検証グリッドで、打った文字が 1 文字ずつ置き換わる・入力から焦点が外れるのを直した**。セルに 2 文字目を打つと 1 文字目が消える、変換中に入力欄から抜ける、といった状態で、表を続けて埋められなかった。
- 依存ライブラリの脆弱性の指摘を解消した。

## 0.8.0

### 追加

- **ファイルを右クリックして、そのファイルの素性を見られるようにした**（「ファイル情報」）。容量・更新日時・行数・文字コード・改行コード・SHA-256・Git から見た状態が 1 か所に出る。受け取ったファイルが本当に送り主の言うとおりのものか、文字化けの原因がどこにあるか、変更をまだコミットしていないかを、別のツールを開かずに確かめられる。
  - 容量と更新日時は先に出し、ファイル全体を読まないと分からない値（行数・文字コード・SHA-256）は後から追いつく。大きいファイルを右クリックしただけで画面が止まらないようにするため。
  - 文字コードは、BOM と UTF-8 として読めるかどうかで判る範囲だけを答える。当てずっぽうで「たぶん Shift_JIS」と出すと、それを信じて変換して壊すことになるため。
- **AI が、JSON や XML の繰り返し部分を Markdown の表として引用できるようにした**。明細のような並びを、列を落とさず桁もずらさずに文書へ写せる。表に写せなかったもの（さらに枝分かれしている項目・1 行に複数あった項目・上限で載せきれなかった行数）は黙って捨てず、名前か件数で返す。壊れた表は読める形をしているので、写し損ねを人が見つけるのは難しい。

## 0.7.1

### 修正

- **表示言語を日本語以外にしても、日本語のままだった箇所を直した**。検証シートの表そのもの・下の行操作バー・列を右クリックしたときのメニューが、英語や中国語や韓国語を選んでも日本語で出ていた。アプリの主画面なのに切り替わらないため、日本語以外を選んだ人にとっては選んだ意味がほとんど無い状態だった。
  - 大分類の既定の名前だけは、これまでどおり作ったときの言語のまま残る。この名前はファイルの中身として書き込まれるので、後から表示言語を変えたときに書き換わると、自分で付けた名前が勝手に変わったように見えるため。
- **更新のお知らせに出る直近 3 件の内容も、表示言語に合わせるようにした**。0.7.0 で直近 3 件を出すようにしたが、中身が日本語だけだった。

## 0.7.0

### 追加

- **JSON と XML を、木構造で開けるようになった**。設定ファイルや取り込んだデータの中身を、別のツールへ移さずに確かめられる。1 行に詰まった JSON でも、折りたたみながら辿れば構造が見える。**書き換えはできない**（読むだけ）。これらは Markdown と違って正本にしていないので、アプリから編集できるようにすると、どちらが本物か分からなくなるため。
  - 深すぎる入れ子や、外部を参照する宣言（DTD）を含む XML は、読まずに理由を添えて断る。開いただけで意図しない読み込みが起きないようにするため。
  - AI からも読める。節を指すと、その部分だけが返る。丸ごと返すとファイルが大きいほど 1 回の応答が膨らむので、既定は 2 世代までで切り、切った先には「あと何個ぶら下がっているか」を添える。黙って縮めると、子が少ないのか無いのかが区別できなくなる。
- **検証シートのセルから、別の箇所や別のファイルへ飛べるようになった**。手順に出てくる設計書の見出しや、前提になる別のシートを、セルに書いておけばその場から開ける。関連する資料を探し直す手間が要らない。同じフォルダの中を指す書き方なので、フォルダごと誰かに渡しても切れない。
- **値がほかの列から決まる列を、計算列として宣言できるようになった**。同じ内容を人が二度書かなくてよくなり、元の列を直せば追随する。計算列は手でも AI からも書き換えられない（書き込もうとすると、どの列が計算列かを添えて断る）。書ける場所と書けない場所が、シートを見ただけで分かる。
- **どこで時間を使っているかを、アプリの中で測れるようにした**（診断パネル）。動きが重いと感じたときに、体感の報告ではなく数字で場所を示せる。

### 変更

- **選択肢のあるセルを、1 クリックで候補ごと開くようにした**。これまでは、セルを選ぶ操作と候補を出す操作で 2 手かかっていた。結果の欄のように選ぶだけの列を何十行も埋める場面で、手数が半分になる。
- **更新のお知らせが、最新の状態でも直近 3 件の内容を出すようになった**。これまで最新のときは何も出ず、「自分が今どこまでのものを使っているか」を確かめる手段が画面の中に無かった。それ以前の分は「もっと見る」からブラウザで一覧を開ける。
- **内蔵の MCP サーバーを、待ち受けに入らずに確かめられるようにした**（`--version` / `--health`）。設定が正しいかどうかを、AI 側から繋ぐ前に切り分けられる。これまでは繋いでみるまで、設定が悪いのかサーバーが動いていないのか分からなかった。
- 見積書・領収書のひな形で、番号の項目名が請求書のままだったのを、それぞれの様式に合った名前に直した。

### 修正

- 依存ライブラリを脆弱性修正版へ更新した。

## 0.6.0

### 追加

- **検証シートを、列が入った状態で新規作成できるようになった**。これまでは白紙から列名を打ち込むところから始める必要があり、その数分が新しいシートを作るたびに丸ごと重複していた。左側の一覧の右上にある ＋ か、フォルダの右クリックから「試験ケース」「観点表」のどちらかを選ぶと、列と色分けが入った状態で作られ、そのままグリッドで開く。
- **同じ値を下の行へまとめて配れるようになった**（Ctrl+D）。結果・実施日・担当のように、何十行も同じ値が続く欄を 1 操作で埋められる。範囲を選んで押すと先頭行の値が下へ配られ、セルを 1 つだけ選んで押すと真上の値を引く。
- **行を控えにできるようになった**。書き直した元の文言を、消していいか毎回悩まずに残しておくための置き場所。控えにした行は表から外れるが、ファイルには残る。「控え 3 行を表示」のように件数が常に出るので、外したこと自体を忘れない。表計算ソフトの非表示行にあたる。
- **見積書と領収書を、請求書と同じ書式で書けるようになった**。`種別` を書き分けるだけで、表題・有効期限・但し書きが切り替わる。請求書のために作った書式をそのまま使えるので、様式ごとに別のひな形を持たなくてよい。
- **内蔵の MCP サーバーを、手元ですぐ使い始められるようになった**。接続設定を開いているフォルダへ書き出せるようにしたので、AI 側の設定ファイルを手で組み立てなくてよい。Node が見つからないときは、どこに入れればよいかを画面に出す。パソコンに Node が入っていても PATH に無い場合は、よくある場所を探しにいく。

### 変更

- 検証グリッドの行操作の並びで、ボタンの文言を「＋ 末尾に行を追加」「選択行の下に複製」に変えた。どこに行が増えるのかが押す前に分かる。窓を狭めたときに文字が 2 行へ折り返してバーの高さが動いていたのも直した。
- 更新のお知らせに出る変更内容を、記号がそのまま見えていたのを整形して表示するようにした。

### 修正

- **検証シートの行に、見た目の番号とは別の変わらない目印を持たせた**。途中に 1 行挿すと以降の番号が全部ずれるため、行を指して何かを指定する仕組み（色分け・行の高さ・控え）が別の行を指してしまう事故が起きていた。目印は行そのものに付くので、行が動いても付いてきた設定はそのまま残る。
- AI が、開いているフォルダの外にあるファイルへ書き込めないようにする判定を厳しくした。フォルダの中に外を指す近道（シンボリックリンク）が置かれている場合、これまでは名前の見た目だけで判定していたため通り抜ける余地があった。実際に行き着く先を確かめてから書くようにした。
- 依存ライブラリを脆弱性修正版へ更新した。

## 0.5.0

### 追加

- **AI が自分の書き換えを確認して履歴に残せるようになった**。これまでは AI に文書を直してもらったあと、何が変わったかを見て記録に残す部分だけ人がアプリに戻る必要があった。`git_status`（今どのブランチで何が変わっているか）/ `git_diff`（変更の中身）/ `git_commit`（記録に残す）を AI から使えるようにしたので、「直して、差分を見せて、記録して」までを続けて頼める。1 日の作業が、名前のないファイルの山ではなく読める履歴として残る。
  - **リモートへ出す操作（push）は含めない**。外に出す前に人が内容を見る手順は変えない。
  - コミット時のチェック（保存前に走る検査）は迂回しない。AI が記録しても、人がコミットしたときと同じ検査を通る。
- **AI から PDF 出力を頼めるようになった**。`export_pdf` で、開いている文書の印刷ダイアログをアプリ側に出させる。PDF の見た目は画面の表示をそのまま使うため、AI 側で別に組み直した結果とズレることがない。返ってくるのは「ダイアログが開いた」までで、保存したかどうかは人の操作になる。
- **AI が検証シートを自分で見つけられるようになった**。これまで検証シート（タブ区切り形式）を読み書きするツールはファイルの場所を渡す必要があり、人がファイル名を教えない限り AI からは探せなかった。検索結果に検証シートも並ぶようになり、表題（`# タイトル:`）で見分けられる。
- **検証グリッドの列寄せを指定できるようになった**。金額の列を右に寄せる、見出しを左に揃えるといった調整ができる。右クリックメニューの「寄せ」から選ぶと、列名・データ・入力欄・大分類の見出しまでまとめて揃う。指定は検証シートに保存されるので、次に開いたときも保たれる。

### 変更

- ソース管理パネルと差分表示が、日本語のままだったのを表示言語に合わせるようにした。英語 / 中国語 / 韓国語で使っている場合も、コミット欄の説明・変更一覧・差分の見出しがその言語で出る。
- frontmatter を読み取れなかったときの説明を、書いた人向けの言い方に変えた。これまでは英語の技術用語（`bad indentation of a mapping entry`）がそのまま出ていた。何行目の何がおかしいのか（字下げ・タブ・項目名の重複・閉じていない引用符など）を、表示言語に合わせて示す。行番号もファイルの先頭から数えた値に直したので、エディターの行番号とそのまま突き合わせられる。

### 修正

- **検証グリッドで、複数行のセルを含む範囲をコピーしても崩れなくなった**。手順や確認内容を箇条書きで書いたセルをコピーして貼り付けると、そのセル 1 個が 2 行に割れ、以降の列がずれていた。Excel / Google Sheets と同じ方式で、改行やタブを含むセルだけを囲んで受け渡すようにした。表計算ソフトとの行き来もそのまま通る。
- **検証グリッドの範囲選択をマウスでできるようにした**。これまで複数セルの選択は矢印キー（Shift + 矢印）だけで、ドラッグしても反応しなかった。押したセルから通ったセルまでが選択範囲になる。
- AI がファイルを書いている最中にアプリやパソコンが落ちても、元のファイルが壊れなくなった。書き換えは差し替え方式にしたので、途中で止まった場合は書き換え前の内容がそのまま残る。検証シートのように 1 回の書き込みで全体を書き戻す種類のファイルで効く。
- AI が、パソコンで扱いづらい名前のファイル（`CON.md` などの予約された名前、コロンを含む名前）を作れないようにした。とくにコロンを含む名前は、書き込めてもファイル一覧に現れない場所へ内容が入ってしまうため拒否する。
- 内蔵 MCP サーバーの接続トークンの照合を、応答時間から中身を推測されない方式に変えた。
- 依存ライブラリを脆弱性修正版へ更新した。

## 0.4.0

### 追加

- **AI から検証シートを直接編集できるようになった**。これまで内蔵の MCP サーバー経由で扱えるのは Markdown の文書だけで、検証シート（タブ区切り形式）には手が出せなかった。「3 行目の結果を OK にして実施日を入れて」のように依頼すると、その行だけが書き換わる。
  - 列は名前で指定するため、列を並び替えても壊れない。
  - 触っていない行はそのまま残るので、変更履歴の差分に余計な行が出ない。
  - 記入途中の値（選択肢にない結果など）もそのまま書き込み、どのセルが型に合っていないかを併せて返す。書きかけの状態を許容する。
  - 追加したツールは `read_tsv`（読み取り）/ `append_tsv_row`（行追加）/ `update_tsv_row`（行更新）の 3 つ。
- **文書を書き始める前に書式を確認できるようになった**。`get_schema` で、文書の種類ごとの必須項目・型・選択肢をそのまま取得できる。これまでは一度書いてから検証エラーを見て直す往復が必要だった。

### 変更

- MCP 経由で検証シートの行が追加 / 更新されたとき、ファイル一覧とプレビューが自動で追従するようになった（Markdown の作成 / 更新と同じ挙動）。

### 修正

- AI に同じ検証シートへの書き込みをまとめて頼むと、同時に処理された分の行が黙って消えることがあった問題を修正。1 枚のシートへの書き込みは順番に処理する。
- 検証シートの 1 セルと 1 ファイルに大きさの上限を設けた。誤って巨大な値を書き込もうとした場合は、ファイルを書き換えずに理由を返す。
- 深く入れ子になった、あるいは同じ内容を大量に参照する frontmatter を読み込むと、処理が長時間止まることがあった問題を修正。読み込む量に上限を設けて、通常の文書の速度は変えずに打ち切るようにした。
- 日本語キーの変換時の深さ検査が一部の文書種別にしか効いていなかった問題を修正。6 種すべてで同じ上限が働く。
