# @md-business/data-tree

JSON と XML を **読んで木構造として見せる**ためのリーダー。md-business のアプリが同じ判定で
同じ木を描けるように、判定とパースをここに集約する。

## 位置づけ — 正本ではない

md-business の正本は Markdown と TSV。JSON / XML は**読むための形式**として扱う。

理由は入口にある。経理で扱う書類の多くが XML / JSON で届く（JP PINT / Peppol の請求書、
ISO 20022 の口座明細、e-Tax の申告データ、銀行・カード・会計サービスの書き出し）。
これらを人が読める形に出せないと、経理の時系列を作る入口が塞がる。

このパッケージは**書き戻さない**。読んで、木にして、返すだけ。

## 公開 API

| 関数 | 役割 |
|---|---|
| `readJsonTree(text, limits?)` | JSON を `DataTreeNode` にする |
| `readXmlTree(text, limits?)` | XML を `DataTreeNode` にする |
| `detectDataFormat(fileName)` | 拡張子から `'json'` / `'xml'` / `null` を返す |
| `readDataFile(fileName, text, limits?)` | 名前でリーダーを選んで読む |

戻り値は例外ではなく結果。読めなかったときは `{ ok: false, problem }` を返し、`problem.kind`
（`size` / `syntax` / `depth` / `nodes` / `doctype` / `entity` / `unsupported`）と
一文の理由、分かる場合は行番号が入る。**黙って空の木を返さない** —— 空のファイルを読んだのか
拒んだのかが区別できなくなると、その差が一番効くのは入力が敵意を持っているときだから。

## XML は DTD を読まない

外部実体参照を無効化する設定を持つのではなく、**そもそも実体を定義する手段を受け付けない**。

- `<!DOCTYPE ...>` を見つけたらそこで拒む（`kind: 'doctype'`）
- 解決するのは `&amp;` `&lt;` `&gt;` `&quot;` `&apos;` と数値文字参照だけ
- それ以外の `&name;` は拒む（`kind: 'entity'`）。黙って消さない

定義する場所がないので、ローカルファイルを読みに行く宣言も、数百バイトから数ギガバイトに
膨らむ宣言も、書ける場所がない。DTD が本当に要るファイルは、その理由を出して拒む。

## 上限

小さいファイルが大きな仕事を要求できるため、3 つを別々に見る。

| 定数 | 既定 | 見るもの |
|---|---|---|
| `MAX_DATA_CHARS` | 4,000,000 | 文字数。パースの前に見る |
| `MAX_DATA_DEPTH` | 100 | 入れ子の深さ。frontmatter と同じ値 |
| `MAX_DATA_NODES` | 200,000 | 作る節点の数。作りながら数える |

`limits` 引数で個別に上書きできる。

JSON の深さは**パースする前にテキスト側で**数える。`JSON.parse` は再帰で降りるため、
深いファイルはパーサの内部でスタックを使い切り、返ってくるのは答えではなくスタックオーバーフロー
になるから。文字列の中の括弧は数えない。

## 既知の制限

数値は JavaScript の表現に従う。double に収まらない精度で書かれた値は丸めて表示される。
書き戻さないので元のファイルは変わらないが、**表示された桁がファイルの桁とは限らない**。
