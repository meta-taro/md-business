仕様は変わったのに、検証シートが古いまま

架空の事例です。会社・人・数字はすべて作りものです
使うもの
基本設計書（spec/v1）と検証シート（TSV）、改版履歴の検査、MCP の validate_document・read_tsv・append_tsv_row・update_tsv_row、デスクトップアプリの表編集
見つかるもの
設計書の版は 1.3 なのに、改版履歴の表は 1.2 で止まっている。1.3 で足した受入条件に対応する行が、検証シートに無い
直し方
改版履歴に 1.3 の行を足し、検証シートに新しい条件の行を足す。結果の列は空けたまま渡し、実施した人が付ける

起きていたこと

ある予約サービスの基本設計書で、キャンセル期限を「前日まで」から「前日 18 時まで」に変えた。 設計書の frontmatter の版は 1.3 に上がったが、改版履歴の表と検証シートはそのままだった。 検証シートは前の条件のまま全行 OK になっていて、見た目には何の問題も無い。

1. 版と改版履歴の食い違いを拾う

エージェントが validate_document で設計書を検査すると、書式は合っているが警告が 1 件出る。

版 1.3 が改版履歴の表にありません。版を上げたら、履歴にその版の行を足してください。

版を上げたことは frontmatter に、何を変えたかは本文に、それぞれ書かれている。 抜けていたのは、その 2 つを結ぶ履歴の 1 行だった。エージェントは差分から変更点を拾い、履歴に 1.3 の行を足す。 修正の印（{~~前日まで~>前日 18 時まで~~}）を残しておけば、相手に出す版で何が変わったかを見せられる。

2. 検証シートの抜けを探す

read_tsv で検証シートを読むと、キャンセル期限の行は「前日に取り消せる」を確かめる 1 行だけだった。 新しい条件で境目になる「前日 17 時 59 分は取り消せる」「前日 18 時 00 分は取り消せない」の行が無い。

エージェントは append_tsv_row で 2 行を足し、古い行の期待結果を update_tsv_row で直す。 直す行は行番号ではなく行 ID で指す。読んでから書くまでの間に、誰かが表の途中へ 1 行挿していても、別の行を書き換えずに済む。

区分        項目              期待結果                 結果
キャンセル  前日 17:59 に取消  取り消せる。返金される   未実施
キャンセル  前日 18:00 に取消  取り消せない旨が出る     未実施

3. 結果は人が付ける

足した行の結果は 未実施 のまま渡す。コードを読んで問題が無さそうでも、自動テストが通っていても、 それは実施ではない。実施する人がデスクトップアプリで検証シートを表として開き、実際に操作して結果を選ぶ。 結果の列はプルダウンで、OK は緑、NG は赤に塗り分けられる。

シートは素の TSV なので、どの行を誰の手で足したかは Git の差分にそのまま出る。

この流れで変わること

「設計書は直したが、検証シートは誰も見ていない」が、警告と差分として表に出る。 全行 OK の古いシートが「確かめ済み」に見え続けることが無くなる。
