ロードマップ

版の番号ではなく、何が出来て何がまだかで並べています。日付の約束はしません。 細かな変更は リリースの一覧、 進行中の話は Issue にあります

済み

  • 文書の形。請求書・基本設計書・検証シート（Markdown と TSV）・API 設計書・DB 設計書（RDB と NoSQL）を、JSON Schema で検査できる形で書ける。
  • デスクトップアプリ。Windows（x64 / ARM64）と macOS。編集・プレビュー・PDF 出力・検証シートの表編集（並べ替えと絞り込みを含む）・全文検索・自動更新。
  • AI エージェントとの接続。アプリに MCP サーバーが入っている。エージェントは文書を探し、読み、作り、検査し、検証シートを 1 行ずつ直せる。書き換えはその場で画面に出る。
  • 提出物としての体裁。目次・見出しと図の参照・PDF のしおり・社外秘などの区分・社内版と提出版の作り分け。
  • 直したところを追う。前の版との比較・修正履歴の書き方（CriticMarkup）・改訂履歴の抜けの検査・行を指す共有リンク。
  • ほかの入口。Chrome 拡張と VS Code 拡張で同じファイルをプレビューできる。

いま

  • 同じ文書を複数人で開く。最初の段として、同じファイルを開いている相手がどの行・どのセルにいるかを画面に出す。この段は文書を書き換えない。
  • このサイト。何が出来るかを、実際の文書の例で見られるようにする。

次

  • 同時編集。居場所が安定したら、Markdown の同時編集、続いて検証シートの行単位の同時編集。正本はファイルと Git のままにし、同時編集は開いている間だけの状態にする。
  • VS Code 拡張で文書を一覧する。ワークスペースにある業務文書を種別ごとに並べる。
  • インストーラへの署名。いまは起動時に「発行元不明」の警告が出る。

その後

  • 調べ物の材料を増やす。通信の記録やログに加えて、パケットキャプチャや画像を AI が根拠として読めるようにする。
  • Google Sheets との往復。Workspace アドオンの審査が通り次第、Marketplace から入れられるようにする。

止めどころ

次に進むか、ここで止めるかは、次の条件で決めます。

  • 続ける: 実際の業務文書がこの形で書かれ、直され、提出されている。不具合や要望が使った人から届いている。
  • 止める・削る: 機能を足しても使われていない。あるいは、足したことで今ある文書の読み書きが壊れる。今ある文書を壊さないことを、新しい機能より優先します。
  • 形を変えない: 書いた文書がそのまま読めなくなる変更はしません。形を変えるときは版を分け、古い形も読めるようにします。

作らないもの

  • サーバーとアカウント。文書は手元のディスクと Git リポジトリにだけ置く。どこかへ預ける仕組みは作らない。
  • 勝手に外へ出す機能。Web への公開や外部への投稿は、人が操作して行う。頼まれれば手段は用意するが、そのときも資格情報は OS の資格情報ストアに置き、Git には入れない。
  • 独自の保存形式。正本は Markdown と TSV のまま。アプリが無くても読めることを守る。
